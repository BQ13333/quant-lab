# Permanent Agent Orchestration

## Decision

Use LangGraph as the first permanent orchestration layer if this project needs durable, recurring agent workflows.

Do not make an agent framework responsible for trading decisions. Agents can coordinate research tasks, generate reports, inspect data quality, open experiment tickets, and summarize model decay. The quant engine must remain deterministic, testable, and auditable.

## Candidate Review

### LangGraph

Best fit for a permanent quant research operating system.

Use it for:

- Durable multi-step workflows.
- Human approvals before promotion or deployment.
- Long-running research tasks that resume after failure.
- Memory and state around experiment review.
- Routing specialist agents such as data QA, feature research, validation, risk, and reporting.

Why:

- Mature open-source project.
- Built for long-running, stateful workflows.
- Clean Python install path.
- Production-oriented concepts like durable execution and human-in-the-loop controls.

### Ruflo

Interesting harness, but too broad for the core platform right now.

Use it only in a sandbox if you want to experiment with agent swarms around Codex/Claude workflows. Do not let it modify the permanent research environment until it has been isolated, reviewed, pinned, and scanned.

Concern:

- Large install surface.
- Many hooks, plugins, daemons, and agent definitions.
- More moving parts than the quant platform needs in phase one.

### MetaGPT

Useful for software-company-style planning, but not the best core for this quant platform.

Use it occasionally for product specs, architecture brainstorming, or generated design docs. Do not build the research runtime around it.

Concern:

- The default pattern is document/code generation with role-played software teams.
- Less directly aligned with durable, auditable financial research workflows.

## Recommended Permanent Loop

The canonical target AI-research workflow is **QForge-20 — the Bounded
Adversarial PhD Quant Research Workflow**. Its approved responsibilities,
research lifecycle, bounded reiteration rules, cloud boundary, and activation
criteria are defined in `docs/QFORGE_20_WORKFLOW.md`.

The following remains the framework-neutral permanent loop:

```text
Idea Intake
  -> Research Agent drafts hypothesis and data requirements
  -> Data QA Agent checks point-in-time availability
  -> Feature Agent creates candidate features
  -> Model Agent trains baseline and ML candidates
  -> Validation Agent runs walk-forward and anti-overfit gates
  -> Risk Agent checks drawdown, exposure, capacity, stress
  -> Report Agent produces model card and tear sheet
  -> Human Approval
  -> Paper Trading Queue
```

Every node writes artifacts to the experiment ledger. No node can skip validation gates.

For the permanent data-and-math operating model, use:

- `docs/QFORGE_20_WORKFLOW.md`
- `docs/MULTI_AGENT_QUANT_SHOP_BLUEPRINT.md`
- `docs/CODEX_CLAUDE_COWORK.md`
- `docs/DATA_AND_MATH_AGENT_FACTORY.md`
- `configs/multi_agent_quant_shop.yaml`
- `configs/agent_mandates.yaml`

Those files define Codex/Claude collaboration, regional data agents, required
data artifacts, source-mining coverage, memory rules, maths-engine workstreams,
and promotion gates.

The source-mining control ledger is generated by:

```bash
uv run python examples/run_source_coverage.py /path/to/authorized-research-corpus
```

The current external-book baseline is `artifacts/source_coverage/SOURCE-COVERAGE-BOOKS-20260707`.
Use `--include-repo-docs` only when the task is to inventory repo docs, vault notes, or generated markdown artifacts.

## First Permanent Agent Roles

- `research_director`: turns ideas into testable hypotheses.
- `data_steward`: validates schemas, missing data, survivorship, and timestamps.
- `feature_engineer`: builds feature pipelines with lineage.
- `modeler`: trains baselines and ML candidates.
- `validation_officer`: runs purged walk-forward tests and adjusted statistics.
- `risk_manager`: enforces portfolio, capacity, and stress constraints.
- `reporting_analyst`: creates model cards, tear sheets, and weekly summaries.

## Phase-One Rule

Start with deterministic Python modules and MLflow/Optuna. Add LangGraph only after the quant tournament can run locally and produce reports without an agent. That keeps the agents as orchestration, not a crutch.

## Local Install

This project is pinned to Python 3.12 through `.python-version`.

```bash
cd quant_lab
uv sync --extra agents
uv run python examples/run_agent_workflow.py
```

The first workflow lives in `src/quant_lab/agents/workflow.py`. It is deterministic by design: no model calls, no tool calls, and no trading permissions. LLM-powered agents can be added behind explicit human-approval gates after the research engine is stable.

## Obsidian Vault

The vault is repo-local at `vault/`. Generated experiment notes link to machine artifacts stored under `artifacts/`.

```bash
uv run python examples/run_asean_research.py
```

That script writes:

- `vault/30_experiments/<run_id>/index.md`
- `vault/30_experiments/<run_id>/validation_report.md`
- `vault/10_maps/ASEAN Quant Research Map.md`

Keep Obsidian as human-readable research memory. Keep large price panels, leaderboards, and coverage files under `artifacts/`.
